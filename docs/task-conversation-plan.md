# Task 持续对话与任务记忆

本文说明 Task 级会话、可靠输入、Document 记忆与补充交付的设计。字段和流程见[代码导航](technical-design.md)，数据升级见[迁移规则](upgrades.md)。

## 一条 Task 会话，多个独立 Run

用户只与任务协调者对话，节点不是独立聊天入口。MCP 调用方定义固定 DAG、节点要求、依赖和执行端指派；协调者凭判断与记忆通过 ACP 推进整体目标，不拆解任务或重写计划。固定 DAG 不规定唯一工具调用路线。所有节点交付有效是整体完成的必要条件，仍须协调者明确判断完成，服务不自动宣告成功。

领域工作由 ACP 执行端承担；协调者判断证据是否足够、是否需要澄清及新事实的全局影响。服务负责准入、派发意图、不可变账本和可靠收尾。

一个 Task 始终绑定同一协调员逻辑会话。Run 记录一次有明确意图和预算的业务执行，SDK 内部任务另行管理。完成、取消或未来触发耗尽后仍可继续 Task 对话；终结 Run 保持不可变。

同一 Task 至多一个协调所有者和一个活动业务 Run。复用 SDK 的模型循环、inbox 和压缩，不另建节点调度器。空闲 Harness 可以关闭；重新打开必须验证原绑定。已绑定的会话文件、身份或任务记忆缺失时拒绝继续，不能创建空会话冒充恢复。

执行准入与对话分离：

- 普通消息不启动空闲 ACP 工作，也不回答待决问题。等待期间可以讨论，但只有明确的问题回答才能解除业务等待。
- 额外执行需要显式补充意图。活动 Run 内追加工作不重置预算；终结后以同一 Task 的成功 Run 为基线创建补充 Run，不把失败、取消或中断 Run 当作重试入口。
- 暂停未来触发后仍可对话。显式补充仍检查截止时间、执行端、资源和不确定结果。
- 模型请求、ACP 执行和工程收尾分别受限。模型请求在 provider 入口持久计数，工具不重复计数；本轮已准入的决定仍须通过当前授权、状态和时限检查。回答不重置额度，普通消息不延长 Run、问题或原 ACP 会话的期限。
- 提问、完成和失败决定独占工具批次；接入在执行前检查批次数量和终止决定，不依赖提示词保证状态一致性。模型纠正仍使用原额度。额度只限制下一次模型请求，不能把收尾也变成一次需要额度的模型行动。

## 上下文、资源与收尾

[协调接入](../src/integrations/coordinator/coordinator.ts)在 SDK 的输入观察屏障之后提供[有界账本视图](../src/integrations/coordinator/context.ts)，包含固定要求、绑定执行、相关事实、输出摘要及当前模型额度。完整内容按需读取，不要求模型重复查询已经取得的证据。记忆维护由信息价值决定，不以每个节点都写笔记为目标。

模型额度包括失败请求和 SDK 压缩请求。ACP turn、会话寿命、执行时长和截止时间分别约束；字段与默认值见[任务契约](../src/protocol/task-contract.ts)。

业务停止、SDK 终止和资源关闭是不同阶段。模型明确完成、失败或提问时，先提交业务决定，再由 SDK 正常结束该输入；不因业务状态变化而提前关闭 Harness。系统取消、超时或额度耗尽时，先阻止新工作，再调用有界 SDK abort 处理在途任务和回执，最后 close。回执保留实际业务停止原因，不以关闭异常替代原因，也不把 unanswered 改成 done。

[监督器](../src/tasks/supervisor.ts)持有协调所有者直至收尾完成。[应用装配](../src/application/task-runtime.ts)停服时关闭业务准入及 Run 写入，但保留回执服务和存储直至所有者退出。收尾失败须报告并停止服务，不能静默继续。崩溃留下的终结 Run 仍只读核对已提交记录，不运行模型或 ACP 补齐；业务结果与 SDK 回执不宣称跨库原子。

## 输入可靠性与公开记录

[TaskConversations](../src/tasks/conversations.ts)先在业务 SQLite 接收输入，再由协调接入使用稳定消息身份提交 SDK inbox。普通消息与明确回答共享 Task 级请求键：相同规范化请求返回原回执，不同内容或输入种类冲突。[TaskRuns](../src/tasks/runs.ts)将回答与 Run 续接、补充意图与新 Run 分别原子提交。

业务库与 durable 库不是一个事务。提交后回执未落库的恢复必须找回同一 requestId，不创建新输入或重放 ACP。终结 Run 的回执与公开输出可以只读对账，不能为补齐展示而重新运行模型或工具。

回执记录输入的处理阶段，采纳情况和执行结果由公开对话与 Run 记录表达。公开记录只包含用户消息、协调员公开文本、问题、总结和失败说明，不公开思维、内部提示或 SDK 工具日志。分页读取不推进执行。

收到消息不打断活动 ACP turn，也不阻止已有输出落库。新派发、验收、提问和完成前必须处理尚未判定相关性的本轮输入。派发后新增的消息若不影响交付，协调者可以在验收时明确审查全部新增消息并说明理由，无须额外 ACP turn；遗漏消息或上游交付变化仍阻止验收，原 turn 保持不变。模型调用始终绑定原准入身份和具体 Run，不能悄悄改绑到最新 Run。取消保留已接收消息，并明确报告未执行输入的原因。

## 固定要求与补充交付

整体目标供协调者判断，不向各节点全文广播；调用方应将执行端需要的背景和验收要求写入节点定义。协调者选择相关用户消息，并在派发时补充本轮必要背景、澄清问题或补充范围。[上下文构建](../src/tasks/execution-context.ts)在新 ACP 会话中提供完整节点要求，同会话续接只提供本轮要求和当前依据；上游引用与旧交付仅在存在时提供。选中的回答携带原问题，避免短答案失去语义；账本中的消息身份和范围不要求执行端理解。

旧交付使用有界摘录及全文文件引用，ACP 客户端只允许读取当前直接上游和本节点旧交付的精确路径。创建时检查基础上下文大小，派发时检查完整上下文。实际采用的消息、上下游交付和会话身份保留在执行记录中；历史读取不改变执行绑定。节点可选消息仍限于本轮或 Task 级、已观察且未失败的用户消息。

旧交付及验收理由不可变。补充产生新交付；未改变的成果可显式复用，但须保留来源，不能伪报为本轮重新执行。新事实和上游修订要求重新审查受影响结果；未处理的结果不能解锁依赖或支持最终完成。正在执行的下游可以保存输出，但上游交付变化后，旧输入对应的结果不能直接验收。

例如 A 分析、B 成文、C 发布：更新 A 后，协调员审查对 B、C 的影响，ACP 处理获准的局部工作；已发布或发送的外部操作不得自动重复。

已验收的 ACP 会话可有界保留或释放，不并发 prompt、不延长原寿命。原工作明确完成后，获准的新补充可用固定执行端的新会话和旧交付上下文；这不是会话恢复或原操作重试。未验收、已中断或结果不明时禁止以新会话补齐。Task 会话长期保留不承诺 ACP 会话永久存在。

## 三层记忆，业务账本为准

- **业务账本**保存输入、准入、执行、等待和不可变交付，是状态与权限的权威来源。
- **durable 历史与压缩**保存协调上下文，继续使用 SDK 能力。
- **任务 Document**保存对后续判断有用的事实、适用条件、决定、注意事项、经验和未决问题，不逐节点复制账本或完整过程。证据冲突尚未解决时保留冲突和来源，不固化成确定结论。

[任务 Document](../src/integrations/coordinator/memory.ts)使用 conversation scope，以跨越 SDK 内部任务生命周期。笔记保留带类型的来源、适用范围，以及来源陈述或协调员推断的区分。[引用校验](../src/tasks/conversations.ts)核验记录存在及归属，语义和范围由协调者判断。执行专属事实保留对应 Run 与条件；持续默认值须有明确来源支持，历史笔记标明所属 Run。范围不明时保留不确定性，在后续执行需要沿用时澄清。

协调者通过受控工具按 key 增改笔记，只删除明确列出的 key；其他 Run 的笔记保持不变。合并与校验在 Document 提交中完成，外部 MCP 不提供通用写入口。

笔记与账本分别提交，先有业务事实再形成笔记。文档读取失败不能伪装成空记忆继续；fail-open hook 之外，实际 provider 与工具入口仍须拒绝失败上下文。记忆、摘要、用户消息和模型判断都不授予权限，也不能清除不确定结果。

## 使用与实现入口

普通对话使用 `task_message_send`，公开记录使用 `task_message_list`；回答待决问题使用 `task_question_answer`。显式补充通过消息的执行意图与 Run 引用表达。Task、Run、question 和 message 使用明确身份；完整契约与限制见 [task-contract.ts](../src/protocol/task-contract.ts)、[mcp-contract.ts](../src/protocol/mcp-contract.ts)。

任务基础配置与未来触发的管理入口见[控制台说明](web-console.md#操作范围)和 [CLI](cli.md#凭据与任务)。

职责入口：

- [TaskConversations](../src/tasks/conversations.ts)：输入、回执、绑定和公开消息。
- [TaskRuns](../src/tasks/runs.ts)：Run 唯一业务写入口、派发、补充和交付审查。
- [TaskSupervisor](../src/tasks/supervisor.ts)、[NodeSessions](../src/tasks/sessions.ts)：单所有者监督与有界资源。
- [协调接入](../src/integrations/coordinator/coordinator.ts)、[会话存储](../src/integrations/coordinator/storage.ts)：SDK inbox、Document、模型循环与公开投影。

暂不支持 ACP 执行中即时插话、自动 session/load/resume、未知结果强制恢复和跨 Task 记忆；其他暂缓能力见[总体方案](design-proposal.md#当前范围与暂缓能力)。
